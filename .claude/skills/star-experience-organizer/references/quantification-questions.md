# 정량화 & 맥락 유도 질문 패턴

## 1. 모호 표현 체크리스트

아래 표현이 나오면 "정량화 필요" 신호로 간주하고 되묻는다.

| 모호 표현 | 되물어야 할 것 |
|---|---|
| 많이 / 크게 / 대폭 | 구체적으로 몇 % / 몇 배 / 몇 건? |
| 열심히 / 노력해서 | 구체적으로 무엇을 했나 (방법, 툴, 횟수) |
| 오랫동안 / 한참 | 정확히 며칠/몇 주/몇 개월? |
| 여러 번 / 자주 | 정확히 몇 회? 어떤 주기로? |
| 성공적으로 / 잘 됐다 | 성공 여부를 판단한 기준은? 비교 대상(before/after)은? |
| 다양한 사람들과 | 몇 명? 어떤 역할의 사람들(직군/직급/이해관계자)? |
| 좋은 반응 | 정량 지표(평점, 재구매율, 응답률) 또는 구체적 피드백 인용 |

## 1-1. "완료 서술"을 Result로 착각하지 않기 (중요)

Result 자리에 아래 같은 문장이 오면, **문법적으로는 멀쩡해도 정량화 여부와 무관하게
Result가 아니라 Action/Task의 재진술**이다. 반드시 되묻는다.

| 완료 서술 (Result 아님) | 왜 Result가 아닌가 | 되물어야 할 것 |
|---|---|---|
| "~을 제출했다 / 완료했다 / 마무리했다" | 제출·완료는 Action의 끝일 뿐, 그 결과 무엇이 어떻게 됐는지가 없음 | 제출 후 평가/심사/피드백/등수는? 채택됐나? |
| "~를 남겼다 / 정리했다 / 설계했다" | 산출물을 만들었다는 것도 Action이지 성과가 아님 | 그 설계/산출물이 실제로 어떤 효과를 냈나? (평가받았다면 몇 점/몇 등, 안 받았다면 왜 아직 결과가 없는지) |
| "~에 참여했다 / 진행했다" | 참여 여부는 Task/Action 영역 | 참여한 결과 무슨 성과·순위·평가가 있었나? |
| "개인별 기여는 추가 확인 필요" 같은 미확정 표현이 Result에 남아있음 | 본인 몫의 성과가 아직 분리되지 않음 | 자소서/면접에 쓰려면 본인 기여분을 먼저 확정해야 함 — 확정 안 되면 이 경험은 보류하거나 정성적 기여로만 기록 |

**판별 기준**: Result 문장에서 동사를 지웠을 때 "그래서 뭐가 좋아졌는데?"라는 질문에
답이 안 나오면 그건 Result가 아니라 Action 요약이다. 예를 들어 "제안서를 제출했다"는
"그래서?"에 답이 없다. "제안서가 대상팀 30팀 중 3위(본선 진출)를 했다"는 답이 된다.

공모전/해커톤류 경험은 특히 이 함정에 잘 빠진다 — "마감까지 산출물을 완성했다"에서
멈추기 쉬우므로 §4의 "공모전 / 해커톤" 질문을 반드시 확인한다.

## 2. 우선순위

1. **Result 수치** — 없으면 최우선으로 되묻는다. 성과가 없으면 자소서/면접에서 설득력이 급감하기 때문.
2. **Action 구체성** — "무엇을 어떻게" 했는지 방법론이 없으면 역량이 드러나지 않는다.
3. **Situation/Task 디테일** — 규모/기간/역할이 흐릿하면 신뢰도가 떨어진다.

한 턴에 1~2개 질문만 던진다. 질문 몰아치기는 사용자를 지치게 한다.

## 3. 맥락이 안 잡힐 때 (Situation/Task 자체가 텅 빈 경우)

정량화 질문보다 먼저 아래를 확인한다:

- 언제, 어떤 조직/팀/과목에서 있었던 일인가요? (규모: 인원 수, 기간)
- 그 상황에서 해결해야 했던 문제나 목표는 무엇이었나요?
- 그 안에서 본인이 맡은 역할은 정확히 무엇이었나요? (팀 전체가 아니라 "나")

## 4. Result 정량화 질문 (상황별)

**팀 프로젝트 / 학교 과제**
- 결과물의 평가 기준이 있었나요? (점수, 등수, 채택 여부)
- 프로젝트로 해결한 문제가 이전보다 얼마나 개선됐나요? (시간 단축, 오류 감소 등)

**영업 / 마케팅 / 홍보**
- 매출/전환율/팔로워/조회수가 몇 % 또는 몇 건 변화했나요?
- 비교 기준(전월 대비, 목표 대비, 동종 캠페인 대비)이 있나요?

**개발 / 데이터**
- 처리 시간, 오류율, 사용자 수, 트래픽이 구체적으로 얼마나 변했나요?
- 코드/시스템 개선이라면 before/after 수치가 있나요?

**서비스 / CS / 응대**
- 응대 건수, 해결률, 만족도 점수, 재문의율 등이 있나요?

**리더십 / 조직 운영**
- 이끈 인원 수, 목표 달성률, 참여율/이탈률 변화가 있나요?

**공모전 / 해커톤**
- 수상했나요? 몇 등, 어떤 상? (본선 진출도 성과 — 몇 팀 중 통과했는지)
- 심사위원 평가 점수나 코멘트가 있었나요?
- 데모/프로토타입에 성능 지표가 있나요? (정확도, 처리 속도, 오차율 등)
- 아직 결과 발표 전이라면, 그 사실 자체를 명시하고 "결과 미확정"으로 기록한다 — 없는 등수를 지어내지 않는다.
- 팀 프로젝트라면 본인이 맡은 부분의 기여도를 먼저 명확히 한다 (전체 팀 성과 ≠ 본인 성과).

## 5. 수치가 정말 없는 경우

사용자가 "수치는 없다"고 명확히 답하면 억지로 만들어내지 않는다. 대신:
- 정성적 변화를 최대한 구체적으로 서술하게 한다 (누가, 무엇을, 어떻게 달라졌다고 말했는지 — 인용 가능하면 인용).
- Result 칸에 "[정성적 성과]"로 표시하고 그대로 기록한다.
